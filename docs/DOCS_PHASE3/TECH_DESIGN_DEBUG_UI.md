# Technical Design — Debug/Performance Frontend (Streamlit) for PVCFC RAG API

Author: PVCFC Engineering
Date: 2025-09-16
Status: Draft for review
Scope: Debug/optimization UI (non-production) covering items (1)–(6) and UI ingest/OCR button

## 0. Purpose & Principles

This document specifies a developer-focused frontend (Streamlit) to debug, profile, and iterate on the RAG pipeline. It is not for production. Priorities:
- Transparent: expose every stage (transform → retrieval → rerank → generation → CoVe → optional Vision).
- Controllable: knobs for HyDE, k values, reranker, tiers (light/heavy), verification modes.
- Inspectable: view citations, open PDF page/region, highlight mentions.
- Measurable: show latencies, token usage, cache hits, request/trace IDs, metrics.
- Extensible: quick integration with one-click ingest/OCR and report templating.

References: see docs/TECH_DESIGN_INGEST_AND_VISION.md (ingest + vision verification design).


## 1. Feature Set (mapped to your items)

1) Debug & performance optimization UI
- Live timeline (per request) with stage latencies: transform, retrieval (BM25/FAISS), rerank, generation, CoVe, (optional) vision verify.
- Request builder with knobs: HyDE on/off, HyDE count, k_bm25, k_faiss, rrf_k, top_k context, expand_parent, reranker method, LLM tier selection (light/heavy), verification mode (never/auto/always), language.
- Metrics panel: tokens (if available), cache hit rate, citation count, confidence, Prometheus scraped metrics summary.
- Log/trace view: show trace_id, structured logs tail; filter by request_id.

2) Click citation → open PDF at exact page/region
- Citation panel lists sources (doc_id, page, bbox, score).
- Clicking a citation opens a modal with the rendered page image and overlays highlighting bbox (if available). If bbox missing, show full page and scroll to approximate location using text search.
- Support multi-citation navigation within modal.

3) Report generation via template
- Template manager (Markdown/Jinja2 initially; optional .docx later):
  - Choose template → fill from sub-queries/sections generated by /report → preview → export (Markdown/PDF/Docx).
- Provide built-in sample template for quick testing; allow user import.

4) Highlight mentions across pages
- Terms panel auto-extracts key entities (e.g., equipment tags) from the answer and/or query.
- Toggle to highlight these terms across all relevant pages; uses:
  - Vector PDFs: text coordinates (if available) or PyMuPDF text search to compute bboxes.
  - Scanned PDFs: requires OCR token boxes (HOCR/ALTO) generated during ingest; fallback to no precise highlight if not available.

5) LLM tier introspection (light vs heavy) (+ embedding optional)
- A/B view: run the same request with light and heavy tiers, side-by-side outputs with timings, tokens, model names.
- Optional embed view: compute query embedding and top-k doc embeddings; plot 2D projection (PCA/UMAP) with similarity distances.

6) Debug-first posture and strategy
- Expose all parameters, show internal artifacts (transformed query, hyde docs, pre/post RRF rankings, rerank scores, prompts/summaries where safe).
- Scenario recording: save/load request configs and results for replay.
- Comparison runs: diff latency and quality metrics between runs.
- Integrate with one-click ingest/OCR: start jobs, view progress/logs, reload indices, rollback last snapshot if needed.


## 2. UX Flows (high-level)

- Home (Dashboard): quick status, last requests, charts (latency percentiles), buttons to go to Query Lab, Report Lab, Ingest.
- Query Lab:
  - Left sidebar: request builder knobs.
  - Main:
    - Tabs: Overview | Retrieval | Rerank | Generation | Citations | Vision Verify | Metrics | Logs
    - Overview: answer, warnings, confidence, breakdown.
    - Retrieval: two lists (BM25, FAISS), then fused RRF list with ranks/scores.
    - Rerank: before/after lists with scores; explanation from reranker.
    - Generation: prompt snapshot (redacted), model, tokens (if available), timing.
    - Citations: table; clicking opens PDF modal at page/region.
    - Vision Verify (optional): per-claim checks, pages examined, corrections applied.
    - Metrics: counters (Prometheus samples) + small charts.
    - Logs: tail requests.jsonl filtered by trace_id.
- Report Lab:
  - Topic + sub-queries, template chooser, render preview, export.
- Ingest:
  - Upload or folder path; options (ocr, language); start; show job list with status/percent/log tail; button to reload indices; snapshot history and rollback.


## 3. Architecture & Integration

- Stack: Streamlit + custom components (HTML/JS) for advanced PDF overlays; Python backends calling FastAPI endpoints.
- API usage:
  - /ask, /locate, /report (existing)
  - /metrics (Prometheus text) for high-level sampling
  - /index-stats (existing) summary
  - /ingest/start, /ingest/status/{job_id}, /indices/reload (as designed in TECH_DESIGN_INGEST_AND_VISION.md)
- Artifacts:
  - Pre-rendered page images: artifacts/pages/{doc_id}/{page}.png (ingest will create)
  - Citation bbox mapping (optional initial), else derive via PyMuPDF search or OCR token maps
- State:
  - Local session state for current run; saved scenarios as JSON in streamlit_app/data/scenarios/


## 4. PDF Viewer & Highlight Details

### 4.1 Rendering Strategy
- Preferred: render pages to PNG during ingest at 200–300 DPI and serve via file path → Streamlit displays as image.
- Overlay highlights: use st.components.v1.html with absolute-positioned divs over an <img> with known pixel dimensions; scale bbox from PDF coordinate space to image pixel space.
- Alternative: embed pdf.js in a small HTML component for live text layer highlighting; higher complexity.

### 4.2 Coordinate Mapping
- PDF coordinate origin (PyMuPDF): top-left or bottom-left depending on library output; normalize to a standard (e.g., top-left origin). Store in metadata.
- Scale factor: image_width / pdf_width, image_height / pdf_height → apply to bbox.
- Multiple bboxes per citation possible; support list and highlight all.

### 4.3 Getting BBoxes
- Vector PDFs: during ingest, extract text spans with bboxes using PyMuPDF, associate chunk_id/doc_id/page.
- Scanned PDFs: during OCR, produce HOCR (bbox per token). Persist per page to artifacts/pages/{doc_id}/{page}.hocr.json for fast lookup.
- Fallback: text search for a short snippet and get first occurrence bbox via PyMuPDF.


## 5. Debug Instrumentation

- Pass a correlation ID (trace_id) from UI to API via header X-Trace-ID to match logs.
- Show timing breakdown returned by API (ask: transform_ms, retrieve_ms, rerank_ms, generate_ms, cove_ms).
- Chart latencies per step over last N runs; compute p50/p95 locally.
- Token usage: display if returned by LLM client (Gemini/OpenAI usage metadata); otherwise approximate from text length.
- Scrape /metrics occasionally (every 5–10s throttle) and parse key counters for display.


## 6. Report Generation (Templates)

- Template format v1: Markdown with Jinja2 vars.
  - Example variables: topic, sections (heading, content, citations), summary, meta.
- Flow:
  1) Call /report to get structured sections.
  2) Render into template → preview.
  3) Export as .md; optional convert to .docx via `python-docx` (Phase 2) or to PDF via `pandoc` if available.
- Provide built-in sample: streamlit_app/templates/report_sample.md
- Template editor in UI for quick adjustments.


## 7. LLM Tier A/B and Embedding View

- A/B:
  - Run query twice: tier=light and tier=heavy; show two columns: answers, confidence, citations, latency, tokens, model.
  - Optional “diff” display of answers.
- Embeddings (optional, can be heavy):
  - Fetch query embedding (via EmbeddingService) and embeddings for top-20 docs; project via PCA/UMAP; plot scatter with hover tooltips.
  - Show cosine similarities and ranks.


## 8. Ingest/OCR Button Integration in UI

- Panel with:
  - File uploader / folder path input
  - Options: OCR mode (auto/force/off), language, chunk parameters
  - Start button → POST /ingest/start → returns job_id
  - Status table polling GET /ingest/status/{job_id}
  - Buttons: Cancel (if supported), Reload Indices (/indices/reload), Rollback to previous snapshot (future)
- Show logs tail per job; link to artifacts snapshot.


## 9. Implementation Plan & Phases

Phase 1 (Core debug UX):
- Query Lab basic: request builder, timeline, retrieval lists, rerank list, generation panel, citations list → PDF modal using pre-rendered pages, highlight fallback without bbox.
- A/B light vs heavy, timing and model display.
- Ingest panel UI wired to /ingest endpoints (happy path), status polling.
- Minimal metrics sampling; log tail by trace_id.

Phase 2 (Deep inspection):
- BBoxes/HOCR in ingest; precise highlights; multi-term highlighting.
- Embedding view (PCA/UMAP) and similarity charts.
- Report Lab with template render & export (.md), basic template editor.
- Vision Verify panel (if feature flagged) to show verified claims and corrected values.

Phase 3 (Power tools):
- Scenario recording/replay, run diff, latency histograms per step.
- Snapshot history view + rollback.
- Advanced pdf.js integration for text layer highlight.


## 10. Additional Suggestions

- Cache Controls: buttons to clear caches (retrieval/rerank/transform) and display hit rates (add /cache-stats endpoint later).
- Presets: “Cost-optimized”, “Accuracy-optimized”, “Debug-verbose” presets that set multiple knobs at once.
- Error sandbox: deliberately trigger timeouts/rate limits to test resiliency and backoff.
- Export run report: save a JSON/HTML bundle of a run for sharing with SMEs.


## 11. Feasibility Assessment

- All items are feasible within Streamlit using:
  - Standard Streamlit widgets for control panels and tabs.
  - st.modal (or custom HTML) for PDF popups; overlays via HTML/CSS.
  - Simple A/B execution by issuing two /ask calls with different tiers.
  - Template rendering (Jinja2) and Markdown export is straightforward.
  - Precise highlights require bbox/HOCR in ingest—documented in TECH_DESIGN_INGEST_AND_VISION.md; otherwise fallback approximations.
  - Embedding visualizations require extra deps (umap-learn or scikit-learn for PCA) and are fine for a debug tool.

Risks & mitigations:
- Large PDFs and many highlights → performance: paginate, lazy-load pages, cap highlights per view.
- Missing bboxes for scanned docs → add HOCR generation; otherwise inform user and skip precise highlight.
- Token usage visibility varies by provider SDK → handle missing data gracefully.


## 12. API Contracts Used by UI (summary)

- POST /ask → AskResponse with meta.breakdown, citations (doc_id, page, bbox?), confidence, warnings.
- POST /report → ReportResponse with sections & citations, summary.
- GET /metrics → Prometheus; sample key counters for UI.
- GET /index-stats → index sizes and flags (bm25/faiss loaded).
- POST /ingest/start → { job_id }
- GET /ingest/status/{job_id} → state, percent, stage, logs_tail
- POST /indices/reload → 200 OK
