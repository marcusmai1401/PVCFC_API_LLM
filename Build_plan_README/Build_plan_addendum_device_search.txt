PHỤ LỤC CẬP NHẬT BUILD PLAN — TÌM KIẾM THEO TAG, NHẢY TRANG, Q&A CHI TIẾT CÓ TRÍCH DẪN

Mục đích: Bổ sung/điều chỉnh cho các Phase 0–4 để đáp ứng yêu cầu mới (ưu tiên độ chính xác, bỏ tiers, bật quét dải trang, Device Overview, report markdown).

Tài liệu tham chiếu: docs/Feature_Device_Search_QA_Spec.md

I) PHASE 1 — INGEST & INDEXING (BỔ SUNG)
1) Phân loại doc_type tự động khi ingest
   - Dùng LLM nhẹ + rule để gắn doc_type ∈ {P&ID, Management of Change, Root Cause Analysis, Technical Data}.
   - Cho phép override bằng cách di chuyển file sang thư mục đúng (hoặc CSV mapping trong tương lai).

2) Metadata chunk phải có `doc_id` và `page`
   - Chuẩn hoá doc_id: `{doc_type}/{slug_file_name}` (duy nhất theo file path).
   - Ghi `page` (1-based) cho mỗi chunk để phục vụ trích dẫn và gom cụm trang.

3) Render trước ảnh trang
   - Lưu `artifacts/pages/{doc_id}/{page}.png` (DPI 200–300) để hỗ trợ preview/nhảy trang chính xác trong UI.

4) Chuẩn hoá tag
   - Uppercase, loại bỏ khoảng trắng/gạch. Ghi nhận đặc thù tag P&ID nhiều dòng (đưa vào ghi chú để phase sau dùng bbox/vision).

II) PHASE 2 — RETRIEVAL & API (ĐIỀU CHỈNH)
1) Bỏ khái niệm tier/mode (light/heavy)
   - Chỉ còn một cấu hình production mặc định, ưu tiên độ chính xác.

2) Bật “quét dải trang” luôn (page-range expansion)
   - Sau retrieve + (rerank sơ bộ), gom kết quả theo doc_id, sắp theo page, tìm cụm trang liên tiếp có tổng điểm cao.
   - Nạp toàn bộ nội dung các trang trong cụm (giới hạn cấu hình, ví dụ max_pages_to_scan=5) làm context chính cho bước sinh trả lời.

3) /ask luôn là Q&A
   - Nếu transform phát hiện LOCATE do có tag nhưng câu không chứa từ khoá định vị, ép về ASK.
   - Trả lời chi tiết, có trích dẫn dạng footnote (doc_id; page), tự động nhận diện ngôn ngữ.

4) Fallback
   - Khi không có kết quả: trả lời tổng quát (nêu rõ thiếu nguồn).
   - Khi có ngữ cảnh nhưng LLM rỗng: tóm tắt từ top-1 chunk, gắn uncited_fallback=true.
   - Cải thiện Gemini client: dùng system_instruction; nếu response.text rỗng, đọc candidates.

III) PHASE 3 — DEMO UI & EVALUATION (ĐIỀU CHỈNH)
1) Device Overview
   - Trang nhập tag → Tabs: Documents/Incidents/Change Requests/Maintenance/Q&A/Report.
   - Documents: cây 4 loại; click mở PDF (native) + nút/preview ảnh trang để chắc nhảy đúng page.
   - Bảng ngoài: manual refresh; filter theo thời gian (30/90/365 ngày).

2) Q&A UI
   - Bỏ lựa chọn execution_mode; tự động nhận diện ngôn ngữ; hiển thị answer + footnote citations.

3) Evaluation
   - Điều chỉnh tiêu chí để kiểm tra “citation đúng trang” và hiệu quả page-range expansion.

IV) PHASE 4 — TỐI ƯU & CHUYỂN GIAO (BỔ SUNG)
1) Hiệu năng
   - FAISS tối ưu cho 1–5M vectors; bật rerank GPU (nếu có) để tăng chất lượng.

2) Metadata/DB
   - Giai đoạn đầu file-based + SQLite cho metadata; chuẩn bị lộ trình nâng cấp Postgres khi mở rộng người dùng/tính năng.

V) NGÔN NGỮ
   - Chuẩn hoá toàn bộ build plan (Phase 0–4) dùng TIẾNG VIỆT.

VI) DoD (bổ sung điểm nhấn)
   - /ask: luôn trả lời chi tiết + footnote citations (doc_id; page); page-range expansion áp dụng mặc định.
   - UI: mở PDF và nhảy đúng trang (page-level) với preview ảnh trang.
   - Report: markdown với trường mặc định; citations cuối report.
